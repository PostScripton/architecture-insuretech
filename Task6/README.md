# Задание 6. Настройка Rate Limiting

## Итоговое решение

Конфигурация: [nginx.conf](nginx.conf).

## Что изменилось в исходном конфиге

Добавлена зона `limit_req_zone` в блоке `http`, которая считает запросы по IP-адресу клиента (`$binary_remote_addr`) с лимитом `10r/m` - 10 запросов в минуту.

В `location /` подключены две директивы:
- `limit_req zone=partner_limit` - применяет лимит без очереди (`burst` не задан, поэтому запрос, превышающий лимит, отклоняется сразу, а не откладывается);
- `limit_req_status 429` - меняет код ответа при превышении лимита с дефолтного `503` на `429 Too Many Requests`.

## Почему без burst и nodelay

Задача - не более 10 запросов в минуту от клиента. Если задать `burst`, часть превышающих лимит запросов будет вставать в очередь (или проходить без задержки при `nodelay`), что фактически позволит пропускать больше 10 запросов в минуту в моменте. Без `burst` каждый запрос сверх лимита сразу получает `429` - это точно соответствует условию задания.

## Проверка

Конфигурация проверена локально: `nginx -t` подтверждает корректность синтаксиса. При замене адресов upstream на тестовый backend и повторных запросах подряд с одного IP первый запрос получает `200`, все последующие в пределах минуты - `429`.
