## Что изменилось в интеграции

В контур добавлен Event Bus (Apache Kafka). Декомпозиция функциональности между core-app, client-info, ins-product-aggregator и ins-comp-settlement не изменилась - изменился только способ обмена данными между тремя интеграциями:

- ins-product-aggregator публикует в Event Bus события об изменении тарифов вместо того, чтобы ждать периодического REST-опроса от core-app и ins-comp-settlement.
- core-app и ins-comp-settlement подписываются на эти события и обновляют свои локальные реплики тарифов по факту изменения, а не раз в 15 минут или раз в сутки.
- core-app публикует в Event Bus события об оформлении страховки вместо того, чтобы ins-comp-settlement раз в сутки запрашивал их по REST. ins-comp-settlement подписывается на эти события и формирует реестр для взаиморасчётов из накопленного за день потока событий.

Взаимодействия, не связанные с этими двумя интеграциями (клиент - веб-приложение, веб-приложение и core-app - client-info, оплата через Платёжный сервис, B2B API для партнёров, обращения ins-product-aggregator к внешним API страховых компаний), остаются синхронными REST/HTTP - их изменение не требовалось для решения выявленных проблем.

## Transactional Outbox

Применяется только для событий core-app об оформлении страховки: запись в core-app-db и запись в outbox-таблицу выполняются в одной локальной транзакции, отдельный relay-процесс читает outbox и публикует события в Event Bus. Это защищает финансово значимые данные о выданных полисах от потери и рассинхронизации с состоянием БД при сбое публикации.

Для событий ins-product-aggregator об изменении тарифов Transactional Outbox не используется - это идемпотентные данные о состоянии каталога продуктов, повторная публикация или пропуск одного события не приводят к потере целостности.

## Что осталось из старой архитектуры

БД (core-db, client-info-db, ins-comp-settlement-db) остаются отдельными PostgreSQL-схемами при своих сервисах, как и раньше. Синхронные REST-интеграции с внешними системами (страховые компании, платёжный сервис, партнёры) не меняются, так как переход на событийную модель с внешними системами не входил в задачу.
